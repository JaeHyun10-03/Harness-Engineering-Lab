# 프론트엔드 테스트 기준

## 적용 시점

화면·입력·상태·라우팅·브라우저 저장소·프론트 의존성이 바뀔 때 적용합니다.

아래 항목별 적용·해당 없음과 이유를 task.md에 기록합니다. 적용 항목은 작업의 명령·기대 결과·실행 시점과 연결합니다.

## 확인 항목

| ID | 대상 | 테스트 방법 | 통과 기준 | 남길 증거 |
| --- | --- | --- | --- | --- |
| FE-01 | 빌드·타입·정적 확인 | 실제 배포 빌드와 프로젝트 타입·정적 검사 실행 | 새 오류 0건. 경고는 원인과 처리 기록 | 빌드·검사 로그 |
| FE-02 | 입력과 상태 | 정상·빈 값·최대 길이·잘못된 형식·중복 클릭·로딩·빈 결과 확인 | 명세대로 안내하며 중복 저장·잘못된 상태 전이 없음 | 컴포넌트 테스트 |
| FE-03 | API 실패·경쟁 | 오류·지연·취소·응답 순서 역전·오프라인 재현 | 오래된 응답이 최신 상태를 덮지 않고 로딩·재시도·실패 안내 정상 | 통제된 API 응답 테스트 |
| FE-04 | 화면·브라우저 | 계획에 정한 브라우저·모바일 폭·확대·긴 텍스트로 핵심 화면 확인 | 필수 조작 요소 가림·잘림·의도하지 않은 가로 스크롤 없음 | 화면 목록·스크린샷·차이 설명 |
| FE-05 | 접근성 | 키보드 이동·포커스 복구·입력 레이블·오류 읽기·대비 확인 | 채택한 WCAG 2.2 A/AA 항목 통과. 자동 도구와 수동 키보드 확인 병행 | 적용 항목·자동 결과·수동 기록 |
| FE-06 | 세션·저장 | 새로고침·직접 URL·로그아웃·저장소 실패 확인 | 인증 정보 노출·다른 사용자 상태 잔존 없음. 서버 권한 테스트는 별도 | 상태 전이 테스트 |
| FE-07 | 성능 | 배포 빌드에서 대표 화면·데이터량·기기·네트워크 조건 고정 | 합의한 로딩·조작·전송량 예산 충족 | LCP·INP 또는 실험용 대체 지표·CLS·전송량 |

## 판정 시 주의

접근성 적용 범위는 기능별로 정하고 전체 표준 인증으로 표현하지 않습니다. Lighthouse 점수 하나로 기능·접근성·실사용 성능을 통과 처리하지 않습니다. 상세 성능은 performance.md를 따릅니다.

필수 항목 실패·미실행·근거 누락은 완료 보류입니다. 수치 목표 미정은 테스트 통과가 아니라 계획 미완료입니다.
