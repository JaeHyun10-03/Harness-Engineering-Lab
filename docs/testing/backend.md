# 백엔드·데이터 테스트 기준

## 적용 시점

API·업무 로직·DB·캐시·메시지·외부 서비스 연동이 바뀔 때 적용합니다.

아래 항목별 적용·해당 없음과 이유를 task.md에 기록합니다. 적용 항목은 작업의 명령·기대 결과·실행 시점과 연결합니다.

## 확인 항목

| ID | 대상 | 테스트 방법 | 통과 기준 | 남길 증거 |
| --- | --- | --- | --- | --- |
| BE-01 | 업무 규칙 | 정상·0·음수·최댓값·반올림·시간대·상태 전이 확인 | 명세와 결과 일치. 금액 등 핵심 계산 오차 없음 | 단위 테스트·경계값 표 |
| BE-02 | API 계약 | 필수·잘못된·과도한 입력, 응답 필드·오류 코드·페이지 경계 확인 | 클라이언트와 약속한 형식·상태 코드 충족 | API·계약 테스트 |
| BE-03 | 실제 DB 통합 | 운영과 같은 DB 종류·주요 버전에서 제약·조회·롤백 테스트 | 부분 저장·제약 누락·트랜잭션 경계 오류 없음 | DB 버전·통합 로그 |

| BE-05 | 마이그레이션 | 빈 DB·기존 데이터에서 스키마 변경, 구버전 앱 호환 확인 | 데이터 보존·배포 순서 충족. 비가역 변경은 전진 복구 전략 검증 | 변경 전후 건수·제약·복구 결과 |

| BE-07 | 비동기·캐시 | 중복·순서 역전·소비 실패·재처리·캐시 만료와 갱신 재현 | 약속한 일관성 충족, 유실·무한 재처리 없음 | 메시지·DB·캐시 결과 |
| BE-08 | 권한·성능 | 역할·소유자별 접근과 대량 데이터 조회 점검 | 권한 위반 0건, 정한 응답·쿼리 예산 충족 | security.md·performance.md 결과 |

## 판정 시 주의

금융 기능에는 잔액·원장 합계·거래 상태 등 불변식을 task.md에 먼저 적습니다. HTTP 성공만 확인하지 말고 최종 저장 상태까지 검사합니다. DB 없는 기능은 관련 항목을 해당 없음으로 처리합니다.

필수 항목 실패·미실행·근거 누락은 완료 보류입니다. 수치 목표 미정은 테스트 통과가 아니라 계획 미완료입니다.
