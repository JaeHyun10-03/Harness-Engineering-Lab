- Python 표준 라이브러리로 기록·검사 보조 도구를 구성합니다. 앱 기술 선택과 별개입니다.

## 2026-09-22: 단계별 테스트 기준 채택

- 작업별 일반 테스트·통합 테스트·핵심 사용자 흐름을 필수 완료 기준에 연결합니다.

- 배포 전후·정기 테스트는 별도 실행 시점으로 구분합니다. 아직 CI나 스케줄러에 연결하지 않았습니다.
- 적용 범위·지표는 testing-policy.md에 기록합니다. 에이전트 분리 방식은 논의 중이며 현재 자체 리뷰 구조를 유지합니다.

## 2026-09-22: 검증 서브에이전트와 영역별 기준 도입

- 앞선 자체 리뷰 방침을 변경하여 메인 + 읽기 전용 verifier를 사용합니다. 에이전트 팀은 도입하지 않습니다.
- 계획 누락과 구현 결과를 별도로 검증하며 메인이 수정·테스트·상태·증거를 관리합니다.
- 프론트·백엔드·제품 AI·DevOps·보안·성능·전체 흐름 기준을 docs/testing/에 나눕니다.
- 적용 기준 ID·기대값·명령·증거를 task.md에 연결합니다. 기술 선택 전 임의의 목표 수치는 확정하지 않습니다.
- 호출 요구는 지침이며, Python이 독립 호출을 기술적으로 증명하지는 않습니다. 실제 Claude 세션 검증은 별도 실험으로 남깁니다.

## 리뷰 무한 반복 방지

- 최초 리뷰 1회 + 재리뷰 2회. 선택적 개선은 완료를 막지 않습니다.
- 결과 리뷰 시작 회차를 프로그램에 등록하고 세 번째 실패 시 waiting으로 전환합니다.
- 사용자 허락 후에만 1회씩 연장하며 회차와 보고서를 보존합니다. 계획 리뷰 한도는 지침으로 적용합니다.

## 2026-09-22: 하네스 강화 — 지침을 프로그램 강제로 전환

- 배경: 평가에서 verify 없이 위조한 증거로 complete 통과, .claude 설정 무방비, Bash 무통제, done 이후 Stop 반복 차단, 상태 손상 시 교착을 실증.
- 사용자 선택: 하네스 핵심 파일은 완전 잠금 대신 단계 게이트(implementing에서만 수정). Bash는 파괴적 git·삭제 명령만 차단하고 일반 커밋은 허용.
- 편집 게이트는 허용 목록 방식으로 전환. 증거·상태 파일은 permissions.deny와 Hook으로 이중 거부.
- verifier 호출을 Agent Hook이 기록하고 review·start가 기록을 요구. 기록은 호출 시도만 증명함을 명시.
- Stop은 done을 통과시킨다. 완료 후 변경은 다음 작업의 지문이 잡는다.
- 설명서 그림은 docs/assets로 이동. 리뷰 반복 제한 본문은 testing-policy.md 한 곳에 둔다.
