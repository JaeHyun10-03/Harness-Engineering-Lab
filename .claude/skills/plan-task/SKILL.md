name: plan-task
description: 새 개발 요청을 목표·범위·완료 기준이 있는 작업으로 정리한다. 단순 설명 질문에는 사용하지 않는다.
---

1. `.claude/tasks/index.md`와 `python3 .claude/hooks/workflow.py status`로 기존 작업을 확인한다.
2. 관련 코드·실행 설정·기존 테스트를 읽는다. 선택 이유가 필요하면 `docs/decisions.md`를 읽는다.
3. 중요한 선택이 남으면 장단점을 짧게 설명하고 사용자 결정을 받는다.
4. `python3 .claude/hooks/workflow.py new <id>`로 작업을 만든다. ID는 소문자·숫자·하이픈이다.
5. 생성된 `task.md`를 [작업 양식](templates/task.md)의 항목에 맞게 채운다.
6. 성능 테스트 필요 여부와 이유를 task.md에 기록한다. API·DB 쿼리·동시 처리 등 성능에 영향을 주는 변경은 검토 대상이다. 필요하면 측정 조건·지표·통과 기준을 사용자와 정하고 완료 기준에도 포함한다. 기존 기능 개선은 구현 전에 같은 조건으로 기준 성능을 측정해 결과를 남긴다. 신규 기능은 비교 기준이 없음을 기록한다.
7. docs/testing-policy.md의 영역 선택표와 해당 상세 기준을 읽고 task.md에 적용 여부·기준 ID·명령·기대 결과·시점·증거 위치를 연결한다. verifier를 계획 모드로 호출해 누락을 확인한다. 실제 응답을 작업 폴더의 plan-review.md에 보존하고 필수 누락을 해소한다. 목표·범위를 바꿨다면 다시 검증한다. 호출 불가면 block으로 기록하고 미완료로 보고한다.
8. `progress.md`에 다음 행동을 기록한다. 계획만 요청한 경우 여기서 마친다.
9. 구현까지 요청받았으면 `implement-task` 스킬로 이어간다. 이미 허용된 구현을 다시 승인받지 않는다.

동시에 여러 작업을 생성하지 않는다. 진행 중 작업과 새 요청의 관계가 불명확하면 먼저 확인한다.
