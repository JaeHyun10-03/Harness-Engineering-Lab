---
name: review-task
description: 작업의 완료 기준을 실제 변경과 검사 결과에 대조한다. 검토만 요청받으면 구현하지 않고 발견 사항을 보고한다.
---

1. 메인은 작업의 task.md, 변경 파일 목록, 적용 기준 ID, 최신 evidence/checks.json과 로그 위치를 준비한다. 리뷰 동안 대상 코드를 변경하지 않는다.
2. verifier 서브에이전트를 결과 리뷰 모드로 호출한다. 이전 지적과 처리 내역도 제공한다. verifier가 원문 코드·테스트·증거를 읽도록 경로를 전달한다.
3. 반환된 실제 응답을 [리뷰 양식](templates/review.md)의 독립 검증 결과에 보존하고 메인의 처리 내역을 구분한다. 호출 식별자(제공되는 경우)·시점·대상 snapshot·자료·미확인 범위를 남긴다.
4. 필수 기준 실패·미실행·근거 부족 또는 미해결 차단/중요 지적이 있으면 통과 등록하지 않는다. 호출 실패는 block으로 기록하고 미완료 보고한다. 발견한 결함은 review fail 후 구현·테스트·verifier 리뷰를 반복한다.
5. verifier 통과 권고와 근거를 확인한 뒤 메인이 review pass를 등록하고 progress.md를 정리한 후 complete를 실행한다.
6. complete 성공 후 결과·테스트·남은 한계를 보고한다. verifier는 명령이나 테스트를 실행하지 않았으므로 별도 재실행 검증을 했다고 표현하지 않는다.

리뷰만 요청하거나 활성 작업이 없으면 대상 범위의 읽기 전용 검증과 보고만 수행한다. 개발 상태를 만들거나 바꾸지 않는다.
Python 프로그램은 보고서 등록과 증거 일치만 확인하며 서브에이전트 호출의 진위를 증명하지 않는다.
