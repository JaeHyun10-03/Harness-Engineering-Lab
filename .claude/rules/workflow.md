# 작업 단계

계획 → 구현 → 검사 → 검토 → 완료 순서로 진행한다.

- 계획에는 요청 해석·조사한 사실·질문과 답변, `REQ-번호`별 기대 동작, 목표·범위·완료 기준을 기록한다. 중요한 미결정 사항을 구현으로 넘기지 않는다.
- 모호한 요청은 관련 코드·문서를 먼저 확인하고, 제품 동작을 바꾸는 선택을 사용자에게 1~3개씩 묻는다. 답변 후 새로 생긴 모호함도 재점검한다. 질문이 필요 없으면 근거를 남긴다.
- 기능 작업에 필요한 파일만 읽는다. 전체 문서·이전 작업 기록을 매번 로딩하지 않는다.
- 구현 도중 범위를 바꾸어야 하면 변경 이유와 선택지를 설명한다.
- 구현 중 요구사항이나 테스트 기준이 바뀌면 계획 검증을 다시 받고 start로 갱신한다. 이전 검증·테스트 증거를 새 명세의 근거로 재사용하지 않는다.
- 진행 기록에는 끝낸 일, 남은 문제, 다음 행동을 남긴다. 코드와 기록이 다르면 실제 상태를 조사한다.
- 사용자가 계획만 요청했거나 질문한 경우 개발 완료 흐름을 강제하지 않는다.
- 구현·테스트 실행·상태 변경은 메인이 담당하고, 계획 및 결과 검증은 읽기 전용 verifier 서브에이전트에 요청한다.
