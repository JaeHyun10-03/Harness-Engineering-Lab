# 작업 단계

계획 → 구현 → 검사 → 검토 → 완료 순서로 진행한다.

- 계획에는 목표·범위·완료 기준을 기록한다. 중요한 미결정 사항을 구현으로 넘기지 않는다.
- 기능 작업에 필요한 파일만 읽는다. 전체 문서·이전 작업 기록을 매번 로딩하지 않는다.
- 구현 도중 범위를 바꾸어야 하면 변경 이유와 선택지를 설명한다.
- 진행 기록에는 끝낸 일, 남은 문제, 다음 행동을 남긴다. 코드와 기록이 다르면 실제 상태를 조사한다.
- 사용자가 계획만 요청했거나 질문한 경우 개발 완료 흐름을 강제하지 않는다.
- 구현·테스트 실행·상태 변경은 메인이 담당하고, 계획 및 결과 검증은 읽기 전용 verifier 서브에이전트에 요청한다.
