# 검사와 완료

- `verify` 명령이 실행한 실제 검사 결과를 증거로 사용한다.
- `.claude/checks.json`의 명령은 작업에 맞는 검사여야 한다. 성공만 반환하는 명령으로 대체하지 않는다.
- 검사를 건너뛰거나 실행하지 못했으면 통과로 적지 않는다.
- 코드·설정·요구사항 변경 후 이전 증거는 재사용하지 않는다.
- 계획에서 성능 테스트 필요 여부와 이유를 정한다. 필요하면 완료 기준에 측정 조건·지표·목표를 포함하고 일반 테스트 통과 후 실행한다.
- 성능 테스트의 기준 미달이나 실행 불가는 통과가 아니다. 변경 전후 비교는 같은 조건으로 수행하고 조건 차이가 있으면 명시한다.
- 검토에서는 각 완료 기준을 구현·테스트·실행 증거와 대조한다. 실패하면 수정 후 다시 검사한다.
- `review pass`는 검토 기록을 등록하는 명령일 뿐, 검토의 품질이나 독립성을 증명하지 않는다.
- `complete` 성공 후에만 작업 완료를 선언한다. 대기·중단 시에는 미완료임을 명시한다.

- 테스트 범위·실행 시점은 `docs/testing-policy.md`를 따른다. 계획에서 완료 기준과 시나리오·명령을 연결하고 리뷰에서 누락을 확인한다.
- 해당 앱의 필수 일반 테스트와 핵심 사용자 흐름은 완료 전에 모두 통과해야 한다. 없는 서버·DB·인증 기능을 가정해 테스트를 만들지 않는다.
- 재시도해도 최초 실패·원인을 보존한다. 커버리지 수치만으로 충분한 테스트라고 판정하지 않는다.
- 적용 상세 기준의 ID와 증거를 연결하고 계획·결과를 verifier에게 검증받는다. 필수 근거 부족이나 미해결 차단/중요 지적이 있으면 완료하지 않는다.
- 현재 작업 상태와 최종 증거는 메인 세션이 관리한다. verify 동시 실행과 공유 증거 덮어쓰기를 하지 않는다.

## 리뷰 반복 제한

결과 리뷰는 최초 1회 + 재리뷰 2회, 계획 리뷰도 같은 한도다. 세부 규칙은 `docs/testing-policy.md#리뷰-반복-제한`을 따른다.
verifier 호출 직전에 review-begin을 실행하고, 한도 도달 후에는 사용자 허락이 있을 때만 review-extend로 1회씩 늘린다.
